# Wonder Trail 圖片設計風格規範

版本：1.1  
適用範圍：小航角色、森林／市場／學校場景、道具、漫畫分鏡、獎勵圖、UI 圖片與 AI 生成素材  
目標年齡：3–8 歲兒童及陪玩的大人

這份文件是 Wonder Trail 的圖片單一風格來源。新增圖片時，先遵守本規範，再依場景增加細節。若「漂亮」和「容易看懂、容易點到」衝突，永遠以兒童辨識與操作為優先。

## 1. 一句話風格定義

**溫暖明亮的海島童話探險繪本：柔和繪本卡通角色與物件、簡化色塊、手繪材質、低對比輪廓、柔和自然光與低壓力的遊戲表情。**

英文工作描述：

> warm bright island-fantasy picture-book cartoon, friendly rounded animal characters, soft painterly color blocks, hand-painted wood and woven textures, subtle low-contrast edges, soft tropical daylight, clear readable silhouettes, child-safe composition, gentle joyful expressions, polished mobile game asset

## 2. 視覺優先順序

每一張圖都依下列順序檢查：

1. **角色／可互動物件是否一眼可辨識**
2. **主要動作與情緒是否清楚**
3. **文字與觸控區是否有足夠留白**
4. **光源、材質與色彩是否和 Wonder Trail 一致**
5. **裝飾細節是否增加氣氛，而不是干擾前四項**

禁止用大量細節掩蓋角色姿勢、物件輪廓或操作目標。背景可以豐富，但互動物件周圍必須保留乾淨的辨識區。

## 3. 小航角色規範

### 3.1 固定識別元素

小航是玩家的探險夥伴，不是嚴格的老師或裁判。以下元素在主要角色圖中應保持一致：

- 暖橘／赤褐色狐狸毛，臉部與胸口有明亮奶油色毛色
- 大而友善的藍色眼睛，眼神看向玩家或正在協助的物件
- 棕色探險帽或飛行帽，附藍色鏡片護目鏡
- 藍色圍巾，作為小航最穩定的識別色
- 綠色側背包或探險配件
- 小型指南針、地圖或其他「導航」意象配件
- 身體比例可愛、頭部略大、四肢短而有動作感
- 全身圖要保留尾巴與耳朵，不裁切頭頂、手掌、腳或尾巴尖端

參考原始素材：

- [小航角色](../src/assets/xiaohang-fox.webp)
- [角色設定稿](./04-xiaohang-character-guide.md)

### 3.2 表情與動作

表情要「明顯但不誇張到嚇人」。優先使用：

- 邀請：身體微微前傾，一隻手向前，微笑
- 發現：眼睛明亮、眉毛抬起、手指向物件
- 思考：手托下巴或看向題目，嘴角保持放鬆
- 答對：雙手張開、耳朵抬起、尾巴上揚、眼睛彎起
- 提示：指向可操作位置，表情專注但不焦急
- 慶祝：跳起或揮手，但不能遮住獎勵物件
- 失誤後：鼓勵、陪伴、輕輕搖頭；不可皺眉、責備、哭泣或嘲笑

動作必須回答「小航現在在幫孩子做什麼？」。不要只生成站立正面、雙手垂下的無目的姿勢。

### 3.3 角色視線與構圖

- 角色面部放在畫面上半部或中上部，手機小尺寸仍要看得到眼睛
- 小航看向玩家時，視線朝鏡頭；指引物件時，視線與手勢一起指向目標
- 對話框不要蓋住眼睛、嘴巴、手勢或關鍵道具
- 角色最多佔畫面 35–45%；若是獎勵／情緒特寫可提高到 60%
- 角色與背景之間保留明亮或較低細節的分離區

### 3.4 卡通繪本渲染規則

- 頭部略大、身體圓潤、四肢短而有動作感；避免成人比例或寫實解剖
- 以大面積柔和色塊表現毛色與服裝，細節只保留辨識角色所需的部分
- 外輪廓使用低對比的暖棕色手繪邊緣；不可有厚重黑線、白色描邊或貼紙邊框
- 陰影要柔和並融入色塊，避免塑膠高光、金屬亮面和攝影棚式反射
- 眼睛要大而友善，保留少量清楚高光；表情優先於毛髮紋理
- 角色可以有立體感，但整體視覺必須偏繪本卡通，不得看起來像玩具公仔或寫實 3D 模型
- 同一組角色的頭身比例、眼睛大小、輪廓對比與陰影強度必須一致

## 4. 場景與材質

### 4.1 世界共同基調

所有世界都共享以下視覺語言：

- 熱帶海島的藍天、海水、雲、植物與木平台
- 手繪／繪本式材質，帶有可感知的木紋、藤編、布料與紙張紋理
- 柔和的陽光與暖色反射，不使用冷硬的攝影棚白光
- 物件有輕微接觸陰影，避免浮空
- 背景細節集中在邊緣；互動區維持乾淨
- 以圓角、弧線、柔軟輪廓取代尖銳幾何

### 4.2 森林

關鍵詞：安全、探索、自然寶物、斑駁陽光。

- 主色：葉綠、苔綠、天空藍、暖木棕
- 可加入花叢、樹根、石頭、木箱與柔和光點
- 目標物要有比背景高一級的明度或色相對比
- 不要把目標藏在極暗、極細碎或同色的背景紋理中

參考：[森林背景群](../src/assets/backgrounds/)

### 4.3 市場

關鍵詞：熱鬧但不吵、木頭攤位、三層平台、親切服務。

- 主色：蜂蜜木、奶油黃、珊瑚橘、海島青綠
- 木板、籃子、收銀機、櫃子使用相同的暖木色與深棕描邊
- 商品用鮮明色彩區分，但不可蓋住客人、算式或按鈕
- 客人選品時使用頭像／圓形或半身識別；結帳時使用完整角色
- 收銀機必須有實體支撐或櫃體，不可看起來浮空

參考：[市場素材](../src/assets/market/)

### 4.4 學校／拼注音

關鍵詞：安靜、明亮、聲音書、學習但像遊戲。

- 主色：天空藍、薄荷綠、奶油白、柔和木棕
- 圖片卡與題目卡使用大面積留白，避免像成人考卷
- 注音選項使用三個大按鈕，三者形狀一致，只靠文字與狀態區分
- 答對以綠色亮光、柔和光暈和短句表現；不要使用大紅叉或失敗畫面
- 物件圖片要比文字裝飾更醒目，讓孩子先看圖、再聽聲音、最後選答案

## 5. 色彩系統

色碼是起始基準，不要求每張 AI 圖片逐像素一致；但色彩關係必須一致。

| 用途 | 色彩 | 建議色碼 |
| --- | --- | --- |
| 小航圍巾／海島青 | 清楚的藍綠 | `#2F8F91` |
| 植物／正向狀態 | 柔和葉綠 | `#78A852` |
| 主要互動／獎勵 | 蜂蜜黃 | `#FFD86A` |
| 奶油卡片 | 暖白黃 | `#FFF3C8` |
| 木頭與外框 | 深暖棕 | `#6B4634` |
| 文字 | 深咖啡 | `#493527` |
| 答對亮光 | 安全綠 | `#6CA46C` |
| 答錯／重試 | 淡陶土 | `#C9A89A` |
| 背景天空 | 淺海藍 | `#BFE5E4` |

使用原則：

- 主畫面以 2–3 個主色加中性色為主
- 深暖棕用於文字、描邊、木板邊緣，不要大面積塗滿
- 黃色是可互動、獎勵與聚焦色；不要把所有裝飾都變成黃色
- 綠色代表完成、安心、再試一次；避免用鮮紅色代表錯誤
- 避免霓虹紫、螢光綠、純黑、金屬灰和高對比恐怖陰影

## 6. 光影與輪廓

- 主要光源：左上或上方的溫暖自然光
- 陰影：柔邊、透明度低、略帶暖棕，不要黑色硬陰影
- 物件下方可有接觸陰影，讓它落在木板、籃子或桌面上
- 互動物件可以有柔和外光或呼吸光，但不可像警報燈閃爍
- 角色與物件可使用極輕微暖棕 drop shadow；避免厚重深棕外框、白色描邊包住所有東西
- 重要輪廓要清楚；素材縮到手機寬度後，仍要看得出形狀

建議生成描述：`soft warm daylight, soft painterly shading, low-contrast warm edges, gentle contact shadows, readable silhouette`

避免描述：`thick dark outline, sticker border, white halo, glossy toy 3D, photoreal fur, dramatic hard rim light, deep black shadows, horror lighting, high contrast cinematic lighting`

## 7. 構圖與輸出規格

### 7.1 手機優先

- 主要畫布以直式 `9:16` 為優先，備用 `3:4`
- 重要角色與道具放在中央 70% 安全區
- 上下各保留約 8–12% 安全留白，避免被瀏海、工具列或底部按鈕遮住
- 一個畫面只保留一個主要視覺焦點，次要焦點最多兩個
- 避免把關鍵物件放在最底部、最右側或四角

### 7.2 可操作物件

- 物件輪廓要完整，避免被裁切或與同色背景融合
- 生成圖只負責視覺，不在圖片內生成按鈕、文字、注音或價格
- 物件周圍預留至少一個物件寬度的視覺空間；程式再提供更大的觸控熱區
- 同一組物件要有一致視角、光源、比例與陰影方向

### 7.3 UI 圖片與背景

- 背景可滿版，但不要把重要訊息烙在背景圖裡
- 標題、對話框、答案與提示文字保留在 HTML／React 層，以便調整字體和注音
- 若圖片包含木板、收銀機、籃子等固定框體，必須在規格中標示可放文字的留白區
- 透明角色與道具優先輸出 WebP／PNG；滿版背景優先 WebP／AVIF

目前程式中可對照的尺寸方向：

- 小航透明角色：`420 × 560` WebP
- 地圖方形背景：`900 × 900` WebP
- 市場滿版攤位背景：`1672 × 941` WebP
- 收銀機透明素材：`1326 × 1186` WebP

## 8. 漫畫與對話框

- 漫畫標題是單一視覺標題，不要做成多個像按鈕的標籤
- 對話框依角色語氣選擇：圓潤泡泡代表溫和請求，尖角／爆炸邊代表驚訝或急迫
- 尾巴必須指向正在說話的嘴巴或手，不可指向錯誤角色
- 對話框底色以奶油白、淡米色為主，深棕細線搭配手繪不規則邊緣
- 字體與注音由程式渲染，不在 AI 圖片中生成中文字
- 每個氣泡控制在 1–3 行短句；成人可讀不是唯一標準，3–5 歲也要能靠語音理解
- 對話框不要壓住角色眼睛、嘴巴、手和關鍵道具

## 10. 交付前檢查表

### 角色

- [ ] 一眼看得出是小航或指定動物
- [ ] 小航保留橘毛、藍眼睛、護目鏡、藍圍巾與探險配件
- [ ] 頭身比例圓潤可愛，整體是繪本卡通而非寫實 3D 或玩具公仔
- [ ] 外輪廓低對比、柔和自然，沒有厚黑線、白邊或貼紙感
- [ ] 陰影融入色塊，沒有塑膠高光或過度細碎的毛髮紋理
- [ ] 表情符合情境，沒有責備或恐怖感
- [ ] 沒有裁切耳朵、尾巴、手或道具

### 場景

- [ ] 世界色彩符合森林／市場／學校其中一種基調
- [ ] 主要互動區明亮且不雜亂
- [ ] 物件有接觸陰影，不浮空
- [ ] 背景沒有搶走角色、題目或商品焦點

### UI 與兒童可用性

- [ ] 圖片內沒有需要程式控制的文字
- [ ] 手機直式裁切後，主要內容仍完整
- [ ] 對話框尾巴指向正確角色
- [ ] 答對使用綠色正向狀態，答錯不使用威嚇式紅色
- [ ] 重要物件周圍有足夠留白，程式可提供大觸控區

### 技術

- [ ] 檔案名稱使用 `小寫-kebab-case-v1` 或既有專案命名格式
- [ ] 透明素材使用 PNG／WebP，滿版背景使用 WebP／AVIF
- [ ] 角色與道具輸出至少 1000px 高度的原始檔
- [ ] 已在 390px 手機寬度檢查裁切、重疊與文字空間
- [ ] 已保留原始生成檔與版本號，避免直接覆蓋可回復素材

## 11. 版本與變更原則

- 新圖先以 `-v2`、`-v3` 增量命名，不直接刪除舊素材
- 角色的臉、服裝主色、護目鏡、圍巾與比例屬於穩定識別，不可為單一場景任意改變
- 場景可以換季節、時間與功能，但需保留海島、暖光、手繪材質與圓潤輪廓
- 若新素材和本規範衝突，先記錄「為什麼需要例外」，再決定是否更新規範
- 規範更新後，下一批圖片才採用新版本；已上線素材不做無理由的大範圍替換
